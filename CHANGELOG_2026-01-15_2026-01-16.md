## 🔴 CRITICAL FIX: FileID Contamination Crisis

### Problema Identificato
**Data Scoperta:** 15 Gennaio 2026  
**Gravità:** CRITICA  
**Impatto:** 139 SKU contaminati (22% del catalogo attivo)

**Sintomi:**
- `rawID_FRONT` e `rawID_BACK` puntavano a file di SKU diversi
- Esempio: SKU `CG-2183` aveva rawID_FRONT di `CG-2239`
- Prodotti mostravano foto di altri prodotti nel sistema

**Root Cause Analysis:**
```
Webapp Photo QC → Race Condition nella selezione foto
├── Operatore seleziona foto per SKU A
├── Sistema carica record SKU B (cambio pagina rapido)
├── Conferma salva FileID di SKU A su record SKU B
└── Contaminazione crociata dei riferimenti
```

### Distribuzione Contaminazione

| Prefisso SKU | SKU Contaminati | Percentuale |
|--------------|-----------------|-------------|
| CG | 70 | 50.4% |
| AE | 31 | 22.3% |
| TT | 17 | 12.2% |
| Altri | 21 | 15.1% |
| **TOTALE** | **139** | **22%** |

### Soluzione Implementata

#### 1. Cleanup Scripts (Airtable Scripting)
```javascript
// Script 1: Delete INVENTARIO contaminated records
// Script 2: Delete PROCESS_QUEUE records + duplicates
// Script 3: Reset OLD_INVENTORY to NEEDS_REVIEW
```

**Azione:** Eliminazione record contaminati + reset per re-migrazione

#### 2. Webapp Photo QC v2.1
**File:** `webapp/ai-photo-qc-review.html`

**Fix Implementati:**
- Storage completo dati selezione (non solo record ID)
- Validazione obbligatoria SKU match prima di conferma
- Warning visivo per selezioni mismatched
- Debug mode per troubleshooting

**Codice Chiave:**
```javascript
// PRIMA (v2.0) - Race condition possibile
photoSelection = { recordId: currentRecord.id };

// DOPO (v2.1) - SKU validation obbligatoria
photoSelection = {
  recordId: currentRecord.id,
  sku: currentRecord.fields.SKU,
  front: { fileId, fileName, parentSku },
  back: { fileId, fileName, parentSku }
};

// Validation on confirm
if (selection.front.parentSku !== selection.sku) {
  alert('⚠️ Front photo belongs to different SKU!');
  return;
}
```

## 🟡 W0.7_MIGRATION_BRIDGE v9 — Anti-Duplication

### Problema
Il workflow creava duplicati in PROCESS_QUEUE perché:
- Controllava solo PROCESS_QUEUE per duplicati
- Non controllava INVENTARIO
- Loop path non resettava `Ready_To_Migrate`

### Fix Implementati

#### 1. Sequential Duplicate Checking
```javascript
// Check 1: PROCESS_QUEUE
const queueDuplicates = filterByFormula: `{SKU} = '${sku}'`

// Check 2: INVENTARIO (NEW)
const inventoryDuplicates = filterByFormula: `{SKU} = '${sku}'`

// Decision Logic
if (queueDuplicates.length > 0 || inventoryDuplicates.length > 0) {
  // SKIP - già presente
  logSkipReason(sku, source);
  resetTrigger();
} else {
  // PROCEED - nuovo record
  createProcessQueueRecord();
}
```

#### 2. Error Path Trigger Reset
```javascript
// Update_OLD_INVENTORY_Skip node
fields: {
  'Ready_To_Migrate': 0,  // Reset trigger
  'Migration_Status': 'SKIPPED_DUPLICATE',
  'Migration_Skip_Reason': skipReason
}
```

### Schema Changes
**OLD_INVENTORY Table:**
```
New Fields:
- Migration_Skip_Reason (Long Text)
```

## 🟡 AI Regeneration Trigger Fix

### Problema
La webapp settava `AI_Regenerate_Trigger = true` ma non `AI_Pending_Trigger = true`.
W3 monitora solo `AI_Pending_Trigger`, quindi le rigenerazioni non partivano.

### Flow Atteso vs Reale

**Design (corretto):**
```
Webapp: Rigenera → AI_Regenerate_Trigger = true
Airtable Automation: → AI_Pending_Trigger = true, reset status
W3: AI_Pending_Trigger = true → Process
```

**Realtà (bug):**
```
Webapp: Rigenera → AI_Regenerate_Trigger = true
Airtable Automation: NON configurata completamente
W3: Mai triggera (AI_Pending_Trigger = false)
```

### Fix
**Option A:** Configurare Airtable Automation correttamente
**Option B:** Webapp setta direttamente `AI_Pending_Trigger`

**Implementato:** Option A - Verifica automazione Airtable

## 🟡 T-SHIRT Normalization Fix

### Problema
AI Agent generava `T-SHIRT` ma Airtable accetta solo `TSHIRT`.

### Soluzione
**Node:** `Parse_Agent_Response` in W00_MIGRATION_AI_AGENT

```javascript
// FIX: Normalizza T-SHIRT → TSHIRT
let subcategoryFixed = (parsed.subcategory || "ALTRO").toUpperCase().trim();
subcategoryFixed = subcategoryFixed.replace(/T-SHIRT/g, "TSHIRT");
```

**Casi Gestiti:**
- `T-SHIRT` → `TSHIRT` ✅
- `T-SHIRT CROP` → `TSHIRT CROP` ✅
- `T-SHIRT SPORTIVA` → `TSHIRT SPORTIVA` ✅

## 🟡 Workflow Trigger Audit — W0.7-W4

### Issue Identificato (16 Gennaio)
Audit ha rivelato che W1-W4 scaricano TUTTI i record invece di filtrare solo quelli con trigger attivi.

### Pattern Problematico
```javascript
// CURRENT - Downloads everything
Airtable Node: Get All Records
Then: Filter in IF node

// OPTIMAL - Filter at source
Airtable Node: filterByFormula: "{Trigger_Field} = 1"
```

### Impact
- Performance: Download inutile di migliaia di record
- Race conditions: Processa record già processati
- Timing: Ritardi nel pipeline
